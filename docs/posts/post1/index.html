为什么我改了 a，b 也跟着变了？——把 Python 的变量和对象讲清楚

2026-09-24T12:00:00+08:00 | 7分钟阅读 | 更新于 2026-09-24T12:00:00+08:00

@ WSB-666

一、先看一个让人懵的现象

a = [1, 2, 3]
b = a

b.append(4)

print(a)   # [1, 2, 3, 4]
print(b)   # [1, 2, 3, 4]

明明只动了 b，a 也变了。

再看一个（这个更让人意外）：

a = 1
b = a

b = 2

print(a)   # 1    没变
print(b)   # 2

同样是 b = a，一个会互相影响，一个不会。差别不在"赋值"本身，而在你操作的是什么类型的对象。

要理解这件事，得先把一个根深蒂固的直觉纠正过来。

二、变量不是盒子，而是标签

学 C 的时候我们习惯这样想：变量是一个盒子，赋值就是把值放进盒子里。

Python 不是这样。

在 Python 里：

  • 对象（值）活在内存里，有自己的身份和内容；
  • 变量只是一个名字，是贴在对象上的一张标签。
a = [1, 2, 3]

这句话的意思不是"把 [1,2,3] 装进变量 a"，而是：先创建一个列表对象，然后把名字 a 贴在它上面。

所以 b = a 做的事是——把名字 b 也贴到同一个对象上。现在两个名字指向同一块内存：

        ┌─────────────┐
   a ──▶│  [1, 2, 3]  │◀── b
        └─────────────┘

b.append(4) 改的是那个对象本身，a 和 b 都贴着它，自然都看到了变化。

可以用 id() 验证——它返回对象的内存地址：

a = [1, 2, 3]
b = a

print(id(a) == id(b))   # True，是同一个对象

而第二个例子里：

a = 1
b = a       # a、b 都指向 1

b = 2       # 这一步不是"改 1"，而是给名字 b 重新贴到另一个对象 2 上

初始:  a ──▶ 1 ◀── b
之后:  a ──▶ 1        b ──▶ 2

b = 2 并没有修改数字 1，它只是让 b 改贴到 2 上去了。a 还贴在 1 上，所以没变。

这也解释了一件事：为什么数字不会被"改动"。 因为整数是不可变对象——它一旦被创建，内容就不能改，你只能让它被别的东西替代。

三、可变与不可变：Python 的分界线

Python 把所有类型分成两类：

可变（内容能改） 不可变（内容不能改）
list 列表 int、float、bool
dict 字典 str 字符串
set 集合 tuple 元组
bytearray frozenset、bytes

对于不可变对象，所有"看起来在修改"的操作，其实都是创建一个新对象。

s = "hello"
s2 = s
s2 = s2 + " world"

print(s)    # hello            没变
print(s2)   # hello world      新对象

t = (1, 2, 3)
print(id(t))

t = t + (4,)     # 不是"给元组加了元素"，而是造了个新元组
print(id(t))     # 地址变了

所以字符串的 upper()、replace()、strip() 都返回新字符串，而不是原地修改：

s = "abc"
s.upper()
print(s)          # abc  ← 忘了接收返回值就会以为方法失效

s = s.upper()     # 正确用法
print(s)          # ABC

这是新手很常见的困惑：“为什么我调了 strip() 却没效果？"——因为字符串不可变，你得接住返回值。

四、这个机制会在哪咬你

理解了"标签 + 对象"之后，下面这些现象就都能自己推出来了。

1）列表装进另一个容器，改里面会影响外面

row = [0, 0, 0]
grid = [row] * 3        # 三个位置贴的是同一个 row

grid[0][0] = 9
print(grid)             # [[9, 0, 0], [9, 0, 0], [9, 0, 0]]

你以为复制了三行，其实三行是同一个列表。正确写法：

grid = [[0, 0, 0] for _ in range(3)]   # 每次都造新列表

2）遍历列表时删元素会漏

nums = [1, 2, 3, 4, 5]

for n in nums:
    if n % 2 == 0:
        nums.remove(n)

print(nums)   # [1, 3, 5]? 实际是 [1, 3, 5]... 再试 [1,2,3,4,5,6] 就错了

原因是边遍历边改，索引会错位。稳妥做法是遍历副本或倒序删：

for n in nums[:]:          # 遍历副本
    if n % 2 == 0:
        nums.remove(n)

# 或者
nums = [n for n in nums if n % 2 != 0]   # 生成新列表，最推荐

3）元组"不可变"不等于"里面全都不能变”

t = (1, [2, 3])
t[1].append(4)

print(t)   # (1, [2, 3, 4])  ← 变了

元组的不可变，指的是它自己的三个格子不能换指向。但里面那个列表的内容仍然可以改。这个区别经常被用来出题。

五、拷贝：浅的和深的

想真的复制一份，就得用拷贝。但这里还分两层。

浅拷贝

import copy

a = [1, 2, [3, 4]]
b = a[:]              # 切片
c = a.copy()          # 方法
d = list(a)           # 构造
e = copy.copy(a)      # 标准库

效果：外层是新列表，但里面的元素还是原来那些对象。

b = a[:]
b.append(99)
print(a)      # [1, 2, [3, 4]]      外层独立了 ✓

b[2].append(5)
print(a)      # [1, 2, [3, 4, 5]]   内层还是共享的 ✗

用图看很清楚：

a ──▶ [ 1, 2, ● ]      新外层
b ──▶ [ 1, 2, ● ]  ◀── 这里的 ● 是同一个内层列表

深拷贝

b = copy.deepcopy(a)

连内层也递归复制一份，完全独立。

a = [1, 2, [3, 4]]
b = copy.deepcopy(a)

b[2].append(5)
print(a)   # [1, 2, [3, 4]]      不受影响 ✓

代价是慢，而且遇到循环引用要靠内部记录来兜。只有在嵌套结构确实需要独立时才用，别习惯性天天 deepcopy。

一句话记法：

浅拷贝只复制"外壳"，深拷贝连"内脏"一起复制。

六、函数传参也是同一回事

Python 的参数传递，本质是把实参对象贴到形参名字上。

def add_item(lst):
    lst.append("x")

my = [1, 2]
add_item(my)
print(my)      # [1, 2, 'x']   ← 外面也变了

因为形参 lst 和外面的 my 贴的是同一个列表，append 改的是对象本身。

但如果函数里做的是重新赋值：

def reassign(lst):
    lst = [9, 9]        # 只是让形参改贴到新对象上
    lst.append(0)

my = [1, 2]
reassign(my)
print(my)               # [1, 2]  ← 没变

因为 lst = [9, 9] 只是让"形参这张标签"换了地方，跟外面的 my 没关系了。

所以准确的说法是：

Python 传的是"对象引用的副本"。能改对象的内容，不能换掉调用者手里的对象。

（有人叫它"传值"，有人叫"传引用"，都不太准。记住上面那句更实在。）

七、经典坑：默认参数

这是这个知识点最出名的一个坑：

def add(x, lst=[]):       # ← 危险
    lst.append(x)
    return lst

print(add(1))    # [1]
print(add(2))    # [1, 2]     ← 怎么记住了上次的结果？
print(add(3))    # [1, 2, 3]

原因是：默认值是在函数定义时求值一次，而不是每次调用时重新创建。

所以那个 [] 是唯一的一个列表，函数一直复用同一张标签指向的对象。

正确写法，用 None 占位：

def add(x, lst=None):
    if lst is None:
        lst = []
    lst.append(x)
    return lst

判断依据：只要默认值是可变对象（[]、{}、set()），几乎都是 bug。默认值用 None、数字、字符串、元组这些不可变的就没问题。

顺带一个：+= 的两种命运

a = [1, 2]
b = a
b += [3]              # 列表的 += 是原地修改

print(a)              # [1, 2, 3]  ← 跟着变了

a = (1, 2)
b = a
b += (3,)             # 元组不可变，造了个新元组

print(a)              # (1, 2)     ← 没变

同一个 +=，在可变和不可变对象上表现完全不同：一个原地改，一个造新的。

八、一个判断口诀

遇到"两个变量会不会互相影响"时，问自己三句话：

  1. 它们是同一个对象吗？ → a is b 或 id(a) == id(b)
  2. 这个对象可变吗？ → 列表/字典/集合可变；数字/字符串/元组不可变
  3. 我做的是"改内容"还是"重新赋值"？ → 改内容会互相影响；重新赋值只会让这张标签换地方

三条都想一遍，绝大多数情况就不用猜了。

九、踩坑清单

  1. b = a 不是复制，是给同一个对象贴第二个名字。
  2. 不可变对象的"修改方法"都返回新对象——忘了接收返回值就会以为方法没生效。
  3. [[0]*3]*3 建二维表，三行是同一个列表。用列表推导式。
  4. 遍历列表时删元素会漏项；用列表推导式造新列表最稳。
  5. 元组不可变，但里面的可变元素内容仍可改。
  6. 浅拷贝内层仍共享；嵌套结构要独立得用 copy.deepcopy。
  7. 函数里 lst = [...] 不会影响调用者；lst.append(...) 会。
  8. 默认参数用 []、{} 是坑，用 None 替代。
  9. a is b 判断的是"是不是同一个对象"，a == b 判断"内容是否相等"，别混用。
  10. 小整数（-5~256）和短的字符串有缓存机制，is 偶尔"看起来能用"，但不要依赖——判断相等永远用 ==。

小结

整篇其实只在讲一件事：

变量是标签，对象才是本体。赋值是贴标签，不是搬东西。

由此可以推出全部结论：

  • 不可变对象不能被改，你只能换个对象；
  • 可变对象能被改，所有贴着它的名字都会看到变化；
  • b = a 只是多贴了一张标签，想要独立就得拷贝，嵌套结构要深拷贝；
  • 函数传参是贴标签，所以能改内容、不能换对象；
  • 默认参数只求值一次，所以不能用可变对象当默认值。

这几条串起来之后，那些"明明只改了一处，怎么另一处也变了"的诡异现象，就会变成理所当然的结果。
