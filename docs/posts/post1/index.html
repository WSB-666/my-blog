同样是 b = a，一个会互相影响，一个不会。差别不在“赋值”本身，而在你操作的是什么类型的对象。

要理解这件事，得先把一个根深蒂固的直觉纠正过来。

二、变量不是盒子，而是标签

学 C 的时候我们习惯这样想：变量是一个盒子，赋值就是把值放进盒子里。

Python 不是这样。

在 Python 里：

  • 对象（值）活在内存里，有自己的身份和内容；
  • 变量只是一个名字，是贴在对象上的一张标签。

这句话的意思不是“把 [1,2,3] 装进变量 a”，而是：先创建一个列表对象，然后把名字 a 贴在它上面。

所以 b = a 做的事是——把名字 b 也贴到同一个对象上。现在两个名字指向同一块内存：

b.append(4) 改的是那个对象本身，a 和 b 都贴着它，自然都看到了变化。

b = 2 并没有修改数字 1，它只是让 b 改贴到 2 上去了。a 还贴在 1 上，所以没变。

这也解释了一件事：为什么数字不会被“改动”。 因为整数是不可变对象——它一旦被创建，内容就不能改，你只能让它被别的东西替代。

三、可变与不可变：Python 的分界线

Python 把所有类型分成两类：

可变（内容能改） 不可变（内容不能改）
list 列表 int、float、bool
dict 字典 str 字符串
set 集合 tuple 元组
bytearray frozenset、bytes

对于不可变对象，所有“看起来在修改”的操作，其实都是创建一个新对象。

所以字符串的 upper()、replace()、strip() 都返回新字符串，而不是原地修改：

这是新手很常见的困惑：“为什么我调了 strip() 却没效果？”——因为字符串不可变，你得接住返回值。

八、一个判断口诀

遇到“两个变量会不会互相影响”时，问自己三句话：

  1. 它们是同一个对象吗？ → a is b 或 id(a) == id(b)
  2. 这个对象可变吗？ → 列表/字典/集合可变；数字/字符串/元组不可变
  3. 我做的是“改内容”还是“重新赋值”？ → 改内容会互相影响；重新赋值只会让这张标签换地方

三条都想一遍，绝大多数情况就不用猜了。

九、踩坑清单

  1. b = a 不是复制，是给同一个对象贴第二个名字。
  2. 不可变对象的“修改方法”都返回新对象——忘了接收返回值就会以为方法没生效。
  3. [[0]*3]*3 建二维表，三行是同一个列表。用列表推导式。
  4. 遍历列表时删元素会漏项；用列表推导式造新列表最稳。
  5. 元组不可变，但里面的可变元素内容仍可改。
  6. 浅拷贝内层仍共享；嵌套结构要独立得用 copy.deepcopy。
  7. 函数里 lst = [...] 不会影响调用者；lst.append(...) 会。
  8. 默认参数用 []、{} 是坑，用 None 替代。
  9. a is b 判断的是“是不是同一个对象”，a == b 判断“内容是否相等”，别混用。
  10. 小整数（-5~256）和短的字符串有缓存机制，is 偶尔“看起来能用”，但不要依赖——判断相等永远用 ==。

小结

整篇其实只在讲一件事：

变量是标签，对象才是本体。赋值是贴标签，不是搬东西。

由此可以推出全部结论：

  • 不可变对象不能被改，你只能换个对象；
  • 可变对象能被改，所有贴着它的名字都会看到变化；
  • b = a 只是多贴了一张标签，想要独立就得拷贝，嵌套结构要深拷贝；
  • 函数传参是贴标签，所以能改内容、不能换对象；
  • 默认参数只求值一次，所以不能用可变对象当默认值。

这几条串起来之后，那些“明明只改了一处，怎么另一处也变了”的诡异现象，就会变成理所当然的结果。
