上一篇我把一台机器人“造”进了电脑：URDF 是骨架，Gazebo 是皮肉，ros2_control 是神经。造完之后发现一个更尴尬的事——这台机器人不知道自己在哪。

你可能说：轮速里程计不是一直在发 odom → base_link 的 tf 吗？问题是，让小车原地转两圈再回原点，你会发现它“回家”的位置偏了。轮子打滑、地面摩擦不均，这些误差只进不出，越积越多。IMU 更别提，便宜 MEMS 陀螺仪的零偏漂移，放一晚上能给你漂出十几度。

传感器个个都“半信半疑”，那就需要一门手艺：把多个不靠谱的信息源，融合成一个靠谱的状态估计。这就是滤波器在机器人里干的活。

这篇把 ROS2 里最常打交道的几类滤波器捋一遍：它们分属哪个门派、假设是什么、在软件栈里各自站在哪一环。

一、先分清两种“滤波”

第一次搜资料的时候我直接被“滤波”这个词搞晕了：低通滤波、卡尔曼滤波、粒子滤波、互补滤波……看起来都是滤波，其实根本不是一个层面的东西。

第一类：信号滤波。处理的是一维原始信号——ADC 采回来的电压、超声波测的距离、陀螺仪的角速度。目的是去毛刺、抑噪声，让曲线“好看”。滑动平均、中值滤波、低通滤波都属于这类，几十行代码就能手写一个，ROS2 里通常直接在驱动节点里做掉。

第二类：状态估计。处理的是机器人的状态——位姿、速度这种多维、互相耦合的量。它回答的不是“这个读数噪声有点大怎么抹平”，而是“综合所有传感器的证据，机器人现在最可能在哪、以多快的速度朝哪个方向动”。卡尔曼家族和粒子滤波都是这一类。

一句话：信号滤波让曲线好看，状态估计回答“我在哪”。这篇文章讲的都是第二类。中间还有个夹在两类的互补滤波（Madgwick/Mahony，imu_filter_madgwick 包），用陀螺仪积分加速度计修正，专攻姿态角，算是状态估计里的轻量选手，后面还会提到它。

二、贝叶斯滤波：所有状态估计的祖宗

把 KF、EKF、UKF、PF 拆开看，里面全是同一个循环——贝叶斯滤波：

所有状态估计器，区别只在一个问题：“信念”用什么形状来表示？

  • 用一个高斯分布（均值 + 协方差）表示 → 卡尔曼家族
  • 用一堆带权重的样本点表示 → 粒子滤波

这一个选择，决定了后面的所有差别。

三、卡尔曼家族：高斯世界的最优解

KF：前提是“世界是直的、噪声是钟形的”

标准卡尔曼滤波的假设非常苛刻：系统是线性的，噪声是高斯的。满足这两个条件时，它是数学意义上的最优估计，而且公式出奇地简单——预测一步、修正一步，全程只需要维护一个均值向量和协方差矩阵，快得飞起。

但现实里机器人全是非线性：轮式里程计的 x, y, θ 是三角函数关系，IMU 也是。于是有了两个补丁。

EKF：把曲线当成切线

扩展卡尔曼滤波（EKF）的思路：在工作点附近做泰勒展开，用切线近似曲线。只要非线性不太狠、步长不太大，效果不错。它至今是工程界最常用的状态估计器——没别的，简单、够用、好调。

UKF：不近似曲线，直接在曲线上采样

无迹卡尔曼滤波（UKF）换了个思路：在均值附近精心挑 2n+1 个 sigma 点，让它们完整地过一遍非线性方程，然后对结果统计出新的均值和协方差。不用算雅可比矩阵，对强非线性系统的近似精度比 EKF 好。代价是计算量稍大。

ROS2 里的落地：robot_localization

卡尔曼家族在 ROS2 里的门面是 robot_localization 包，提供 ekf_node 和 ukf_node 两个节点。最经典的用法是融合**轮速里程计（连续、平滑、但漂移）**和 IMU（姿态快、不漂移但噪声大）：

注意 odom0_config 这种 15 位开关的设计——每个传感器只填自己信得过的分量，位姿交给别的源，这就是融合的精髓：不是把所有数据都塞进去，而是让每个传感器只贡献它擅长的维度。

输出的结果是一段平滑的 odom → base_link tf，正好接上你之前学的 TF 链条（就是那篇“杯子为什么不能直接说在这里”的续集）。

家族的死穴：只能有一个峰

高斯分布天生单峰。想象你从电梯出来，可能是 1 楼也可能是 2 楼，两个走廊长得一模一样。高斯信念会硬把两个可能平均成 1.5 楼——一个精确但完全错误的位置。这在定位里比“粗糙但正确”致命得多。

四、粒子滤波：用一群“假想的自己”投票

既然分布形状可能任意，那干脆不猜形状——直接撒一把粒子，每个粒子代表一个“假想的自己”（一份完整的位姿假设），带一个权重。

电梯那个场景它毫不含糊：一半粒子在 1 楼，一半在 2 楼，两个峰各过各的。直到你推门看见红色消防栓，2 楼粒子的权重瞬间暴涨，重采样后 1 楼粒子全军覆没——自然收敛，不需要任何“单峰”假设。非线性、非高斯、多模态，全都不怕。

ROS2 里的落地：Nav2 的 AMCL

粒子滤波在 ROS2 里的代表是 Nav2 的 amcl（自适应蒙特卡洛定位）。它的分工非常明确：在已有地图上，用激光雷达做定位。

还记得 TF 文章里 map → odom → base_link 那条链吗？odom → base_link 是轮速里程计在发，而 map → odom 这一段就是 AMCL 发的——它负责修正里程计的累积漂移：“里程计说你在 (3.2, 1.5)，但对着地图一看，你其实站在 (3.0, 1.6)，差的那截我补上”。这正是 REP-105 的设计：全局修正和局部推算各管一段，互不干扰。

adaptive_kld 值得单独说一句：粒子撒多了浪费算力，撒少了估计不稳，KLD 采样用信息论的方法动态控制粒子数——刚开局全图乱撒时多用粒子，锁定目标后自动减员。这就是名字里“自适应”的含义。

调试时最爽的直观体验：rviz2 里加一个 PoseArray 显示，订阅 /particle_cloud（或 amcl 的粒子话题），你能亲眼看到一团红色的“假想机器人”从漫天散布一步步收缩到一个点——粒子滤波的教科书动图，在自己屏幕上跑出来。

被“绑架”了（机器人被搬走）怎么办？调 reinitialize_global_localization 服务，粒子重新全图乱撒，从头再来。

粒子滤波的死穴：维度灾难

粒子数量随状态维度指数增长。定位的状态就三维（x, y, θ），几百到几千个粒子足够；但 SLAM 的状态包含整张地图——几千维，粒子滤波直接爆炸。历史上 FastSLAM 用“每个粒子带一张小地图”的技巧绕过，但现代主流 SLAM（如 slam_toolbox）已经走了另一条路：图优化。所以粒子滤波的地盘很清晰：低维状态的估计，典型就是定位。

五、一张表看懂区别

维度 KF / EKF / UKF 粒子滤波（MCL/AMCL）
信念表示 一个高斯分布（均值+协方差） 一堆带权重的粒子
系统假设 KF 线性；EKF/UKF 可弱非线性 任意非线性
噪声假设 高斯 任意分布
多峰场景 无能为力（平均出 1.5 楼） 天然支持
计算量 极小（矩阵运算） 大（随维度指数涨）
精度特性 平滑、连续 收缩后也准，但有抖动
ROS2 包 robot_localization（ekf/ukf_node） nav2_amcl
典型任务 里程计+IMU 融合、平滑速度输出 已知地图上的激光定位
死法 被多峰骗死（精确但错误） 粒子全灭/贫乏、CPU 烧死

怎么选，就三句话：

  1. 要把连续运动的传感器（轮速、IMU）融合成平滑的速度和位姿 → 卡尔曼家族，robot_localization
  2. 要在已知地图上定位，环境有对称、歧义的可能 → 粒子滤波，amcl
  3. 嫌高斯单峰不够用，又嫌粒子算不起 → 看看问题能不能降维，或者换 UKF 硬扛

实际机器人的标准姿势是两个都用：ekf_node 在下层管 odom → base_link，amcl 在上层管 map → odom，各守一段 tf，谁也不抢谁的活。

写在最后

回头再看，滤波器本质上是在做信念管理：预测让信念变胖，观测让信念变瘦，不同滤波器的差别只是“胖瘦用什么形状记账”。卡尔曼家族用一条钟形曲线记账，又快又优雅，代价是只认一个峰；粒子滤波撒一把假想的自己投票，什么形状都认，代价是算力和调参。

而“我在哪”只是第一步。地图都没有的时候怎么办？那就轮到 SLAM 登场了——不过那就是下一篇的事了。
